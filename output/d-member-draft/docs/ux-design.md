# 三个核心页面的信息架构与低保真原型（D 侧草稿）

日期：2026-09-09。状态：已并入 JD_select-main。Result/History mock 与新建分析的本地提交状态已接入原有 React/TypeScript/Vite 入口，原有健康接口请求与代理保留。已读实际源码并验证 OpenAPI，仅发现 /api/health；当前不存在 docs/api.md 或业务 schema，不能将附件计划当作已实现接口。真实解析、匹配、保存和历史数据仍待 B/C/A 完成。

关联：[用户流程](user-flow.md)、[测试计划](test-plan.md)。MVP 边界与职责依据附件 MVP_TASK_PLAN.md；a4-integration-checklist.md 仅用于列出后续待确认事项。

## 1. 全局结构

- 主导航：新建分析、匹配结果、历史记录。当前“匹配结果”打开固定示例；未来真实结果由本次匹配或历史详情进入。
- 页面层级：页面标题 → 当前状态 → 核心内容 → 下一步操作。
- 当前页面显著显示“业务数据为本地示例 · 未调用匹配接口 · 未保存”；健康检查可连接真实后端，不得将固定分数称为真实计算结果。
- 详情标识使用服务端返回的 id 字符串。具体采用现有 router 或项目现有导航机制；本文不新增公共 API 或擅自引入路由依赖。
- 电脑宽度内容容器居中且有适当最大宽度；窄屏变为单列。长岗位名、技能、建议、id 和版本号可换行，按钮可换行排列，避免页面横向滚动。
- 复用项目已有页面容器、按钮、提示组件；保留现有 React / TypeScript / Vite。不为了原型新增 Tailwind 或更换框架。

## 2. 页面一：新建分析

```text
┌ 新建分析 [当前导航] ───────────── 历史记录 ┐
│ 新建分析                                 │
│ 1. 简历内容                              │
│ [多行文本：请输入或粘贴简历………………]       │
│ [字段错误 / 输入说明]                    │
│ [解析简历 / 正在解析…]                   │
│ 2. 查看并修正解析结果                    │
│ [教育] [经历] [项目] [技能]              │
│ [编辑入口及确认，具体沿用 B 的组件]       │
│ 3. 岗位 JD                              │
│ [多行文本：请输入岗位职责与要求…………]     │
│ [字段错误 / 输入说明]                    │
│ [开始匹配 / 正在分析…]                   │
│ [Loading 状态或错误提示 + 重试入口]       │
└─────────────────────────────────────────┘
```

| 区域/控件 | 内容与交互 | 状态及边界 |
|---|---|---|
| 简历输入 | 可访问标签“简历内容”、多行文本框、输入说明 | 空字符串及纯空白不允许解析或匹配；提示“请先输入简历内容”；错误后保留文本 |
| 解析按钮 | “解析简历”，调用 B 已有逻辑 | 解析中显示“正在解析…”并禁用；失败后可重试；D 不重写解析器 |
| 解析结果 | 教育、经历、项目、技能；可查看、修正并确认 | 字段结构沿用 B 实际返回；无结果时提示先解析；简历原文改变后旧结果需重新确认 |
| JD 输入 | 可访问标签“岗位 JD”、多行文本框 | 纯空白提示“请先输入岗位 JD”；岗位名如已有控件则复用，不额外扩大本页范围 |
| 匹配按钮 | “开始匹配” | 校验失败不请求；在途禁用，事件处理也拦截重复；待失败/成功后解除锁定 |
| Loading | “正在分析匹配情况，请稍候” | 状态区可被辅助技术读取；不显示虚假百分比；冻结本次有效输入 |
| Error | 可读错误及重试 | 区分解析失败、匹配失败和字段校验；不直接展示原始堆栈、对象或敏感文本 |

新建分析页已提供可操作的本地流程：简历/JD 文本在当前页面会话中保留；空输入会在对应字段给出提示并定位焦点；提交可切换成功/失败模拟，包含 Loading、在途禁用、事件层防重复、失败保留输入和重试。成功始终打开固定 `demo-001`，与当前输入无关，不计算评分、调用业务 API 或保存。真实解析按钮保持禁用，B 仍负责解析及编辑组件；生产请求字段和真实提交由 B/C/A 契约确认后接入。

## 3. 页面二：匹配结果 / 历史详情

```text
┌ 新建分析 ───────────────────── 历史记录 ┐
│ [mock 时：示例数据 · 未连接后端 · 未保存]│
│ [返回]   匹配结果 / 历史详情             │
│ 数据分析实习生                          │
│ 总分 72 / 100        [实际保存状态]      │
│ 匹配分用于辅助判断，不代表录用概率      │
│ 分项得分                                │
│ 必需技能 55   加分技能 12   证据质量 5  │
│ 匹配技能                 缺失技能       │
│ Python · SQL             Tableau        │
│ 改进建议                                │
│ • 补充量化成果                          │
│ • 增加与 Tableau 相关的真实项目证据     │
│ 评分依据 / 证据                         │
│ [实际证据；缺失则明确“暂未提供”]        │
│ 算法版本：rule-v1                       │
│ [返回新建分析] [修改后重新分析]          │
└────────────────────────────────────────┘
```

电脑可将匹配/缺失技能并排；窄屏依次纵向排列。关键解释始终可见，不以鼠标悬停作为唯一访问方式。

### 字段映射与缺失处理

| 字段/区域 | 展示名称与行为 | 缺失或边界 |
|---|---|---|
| id | 用于关联当前结果和历史详情；必要时显示记录标识 | 无 id 时不得构造历史详情链接或声称已保存；不使用数组下标 |
| job_title | 岗位名称，页面主标题 | 空或未返回时“未命名岗位”；不根据技能猜岗位 |
| score | “匹配分”及数值 / 100 | 0 是合法分数；缺失或无效值显示“暂无评分”，不以 0 冒充；不自行重算或修正算法输出 |
| score_breakdown.required_skills | 必需技能得分 | 不将 55 分解释为 55% 命中率 |
| score_breakdown.preferred_skills | 加分技能得分 | 无值显示“暂未提供”，0 正常显示 |
| score_breakdown.evidence_quality | 经历证据质量得分 | 得分不等同于文本证据已可追溯 |
| matched_skills | “匹配技能”，逐项文字或标签 | 空数组“暂无匹配技能”；不虚构已掌握技能 |
| missing_skills | “缺失技能”，逐项展示 | 空数组“未发现缺失技能”，不推导为一定录用 |
| suggestions | “改进建议”，有序或无序列表 | 空数组“暂无改进建议”；实际元素类型待确认，不把对象输出成 [object Object] |
| algorithm_version | “算法版本：…” | 空或缺失“版本信息暂未提供” |
| 评分依据/证据 | 若正式响应有证据，显示技能/分项、原文摘录及可用定位 | 用户提供的 mock 无证据字段，显示“此示例未提供原文证据，暂无法核验逐项评分依据”；不编造摘录或新增生产 evidence 字段 |
| 评分说明 | “匹配分用于辅助判断，不代表录用概率” | 正常结果与历史详情均展示 |
| 返回 / 重新分析 | 返回原入口；修改后重新分析进入新建分析 | 历史原文不存在时提示重新粘贴；重新分析生成新记录，保留旧快照 |

附件提议分项上限 60/20/20，尚未核对当前实现。mock 先展示“得分”并确保样例分项和为 72；在 A/C 确认前不把建议权重写成已冻结的业务事实。

### 页面状态

| 状态 | 页面内容 | 可执行操作 |
|---|---|---|
| normal | 完整结果，mock 标记或真实已确认来源与保存状态 | 返回、历史、重新分析 |
| loading | 主标题与“正在加载匹配结果…”；不显示上次记录的分数 | 返回；不重复触发同一加载 |
| error | “匹配结果加载失败，请重试” | 重试当前 id、返回；不伪装成功 |
| empty | “暂无匹配结果，请先新建分析” | 新建分析；分项空数组不等于整页 empty |
| not-found | “这条分析记录不存在” | 返回历史、新建分析；与网络失败区分 |

静态页可通过独立的“演示状态”控件切换上述状态，明确属于 mock 演示，不能伪装成真实请求失败或真实 Loading。是否采用已有开发预览入口，待查看前端结构后决定。

## 4. 页面三：历史记录

```text
┌ 新建分析 ───────────────── 历史记录 [当前] ┐
│ [mock 时：示例记录 · 未从服务端读取]       │
│ 历史记录                     [新建分析]   │
│ 最近分析（最多展示 10 条）                 │
│ 岗位名称          匹配分  创建时间  操作    │
│ 数据分析实习生    72      …       查看详情 │
│ Python 后端实习生  …      …       查看详情 │
│ [错误或 Loading 状态区域]                 │
└──────────────────────────────────────────┘

空状态：还没有分析记录 → [新建分析]
窄屏：每条转为卡片，包含岗位名、分数、时间、查看详情。
```

| 信息/控件 | 显示与行为 |
|---|---|
| 岗位名称 | 使用记录 job_title，空值为“未命名岗位”；长名称换行 |
| 匹配分数 | score / 100，0 正常显示；缺失不得当作 0 |
| 创建时间 | 根据带时区时间转换为浏览器本地时间，标注“时间按本地时区显示”；不合法或缺失显示“时间暂未提供” |
| 查看详情 | 绑定该条 id；使用稳定 id 作 React key；对 id 进行 URL 编码（若采用 URL 导航） |
| 最近列表 | 优先保持服务端返回顺序，默认最近 10 条；mock 使用固定合成记录和固定带时区时间，不用当前时间伪装新保存 |
| 空历史 | 仅请求成功且 items 为空时展示，或 mock 明确切换 empty；引导新建分析 |
| 加载/失败 | Loading 提示；失败可重试；不能将请求失败当作零记录 |

当前 A 附件描述列表形状为 items/total/limit/offset，正式接入前须核对真实契约。今天不实现服务端分页、编辑标题、删除记录或持久化；不添加对应 API。mock 详情在本地样例中按 id 查找，不发后端请求。
