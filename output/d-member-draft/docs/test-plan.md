## 2. 测试准备与判定原则

- 记录实际分支、提交哈希、未提交变更、前后端启动命令、浏览器版本和窗口宽度。
- 使用下列合成文本，不含真实手机号、邮箱、姓名或密钥。执行时固定输入，保留经过人工确认后的有效输入快照。
- 高/中/低是需求中的定性预期；具体数值范围和固定样例预期分由 C 按已确认公式给出、A/D 复核。D 不自行设置阈值或调整算法凑分。
- 分项和、上限、整数约束按最终确认契约验收；附件建议 60/20/20，不将未核验的建议当作当前实现。
- 每个用例记录实际结果与证据。尚无数值标准时，可检查排序和技能集合，但总分区间判定保留“待 C 确认”。
- 真实详情使用实际响应 id；用例中的不存在 id 与本地 demo id 分开。若实际接口要求 UUID，使用格式合法且确认不存在的测试 UUID。
- 请求失败可在授权的本地浏览器测试中模拟断网；延迟可用浏览器网络节流或已有测试拦截工具。不修改生产 API，不为了测试改后端实现。

## 4. 验收用例

### TC01 完整匹配

- **前置条件**：后续真实环境中 B/C 模块可运行、A 持久化可用；输入与人工修正的传递契约已确认；C 给出本样例可复现的期望分数或区间。
- **输入**：RESUME-FULL + JD-BACKEND。
- **操作步骤**：
  1. 进入新建分析，粘贴简历并点击解析，检查并确认结果。
  2. 粘贴 JD，点击开始匹配一次，等待完成。
  3. 核对总分、分项、匹配/缺失技能、建议、算法版本和证据。
  4. 确认服务端保存成功，再到历史按返回 id 打开本次记录。
- **预期结果**：高分；Python/FastAPI/SQL/数据分析等样例技能被正确识别，缺失项较少；分项符合确认后的公式，证据来自真实输入；总分不低于部分/低匹配样例；评分局限说明可见。结果与历史同 id 数据一致；保存由约定的匹配编排完成，D 不重复创建。
- **当前执行状态**：未执行；依赖 A/B/C，不能用 72 分 mock 判为通过。

### TC02 部分匹配

- **前置条件**：与 TC01 相同；已确认该样例的中等分判据。
- **输入**：RESUME-PARTIAL + JD-BACKEND。
- **操作步骤**：
  1. 新建分析，解析并确认简历，仅保留样例实际包含的技能。
  2. 输入相同 JD，发起匹配。
  3. 核对匹配技能、缺失技能、分项及建议，与 TC01 对照。
- **预期结果**：中等分；Python/Excel 可命中，明确列出 FastAPI、SQL 等缺口；不凭空补全后端经验；建议要求补充真实能力/项目证据。总分区间按 C 确认标准判定；若不符则记录差异，不能在前端改分。
- **当前执行状态**：未执行；具体分数区间待 C 确认。

### TC03 低匹配

- **前置条件**：与 TC01 相同；已确认低匹配判据。
- **输入**：RESUME-LOW + JD-BACKEND。
- **操作步骤**：
  1. 解析市场运营简历，确认未出现其未声明的技术技能。
  2. 粘贴后端 JD，发起匹配。
  3. 对照原文逐项审查 matched_skills、missing_skills、建议与证据。
- **预期结果**：低分；Python/FastAPI/SQL 不能被虚构为已掌握技能；缺口可读；不能因为 JD 提到了某技能就声称简历命中；总分可以包含真实经历质量分，不强制要求为 0。
- **当前执行状态**：未执行；依赖 B/C 真实输出。

### TC04 空输入

- **前置条件**：新建分析 UI 可运行，浏览器可观察请求；已清除上一轮数据。正式后端输入校验单独由 A/B/C 验证。
- **输入**：分别测试空简历+有效 JD、有效简历+空 JD、两者都空，以及仅含空格/换行的输入。
- **操作步骤**：
  1. 按各组合填入文本，尝试点击解析或开始匹配。
  2. 若按钮可触发，观察字段提示与网络请求；用键盘重复校验路径。
  3. 补齐对应输入，再观察错误是否消除、提交是否恢复。
- **预期结果**：空简历不能解析或匹配；空 JD 不能匹配；trim 后为空同样拦截；给出“请先输入简历内容”或“请先输入岗位 JD”；不发送无效请求，不清空其他有效输入。若同时缺失，可显示两个字段提示，焦点定位第一个错误。
- **当前执行状态**：前端校验通过。自动化已覆盖双空、仅空 JD、纯空白、焦点定位、保留有效输入和不发业务请求；真实后端输入校验仍待 A/B/C 联调。

### TC05 同义词

- **前置条件**：C 词典和 B/C 归一化链路可用；两次分析使用相同算法版本与同一 JD。
- **输入**：SYNONYM 的简历 A、简历 B，分别配相同 JD。
- **操作步骤**：
  1. 分别解析并匹配 A、B 两份简历。
  2. 对照技能归一化名称、命中集合、缺失集合和得分。
  3. 在同一简历中重复写入同义词，再检查是否重复计分。
- **预期结果**：PyTorch/pytorch、JS/JavaScript 分别识别为同一技能；仅替换大小写和别名不改变相应命中与评分；重复别名不重复加分，页面不显示重复技能。未支持的词交 C 确认，不由 D 伪造命中。
- **当前执行状态**：未执行；等待 C 词典与真实算法。

### TC06 Loading

- **前置条件**：匹配提交 UI 已接入待测函数；在本地测试中延迟响应数秒；使用有效输入。
- **输入**：RESUME-FULL + JD-BACKEND。
- **操作步骤**：
  1. 点击开始匹配，在响应返回前观察页面。
  2. 用鼠标和键盘尝试再次提交，检查网络请求数。
  3. 释放延迟响应，分别观察成功和失败后的状态。
- **预期结果**：立即出现可读 Loading；提交按钮不可重复触发且事件层拦截在途提交；不显示虚假百分比；成功后进入结果，失败恢复可重试状态；加载不会一直残留。
- **当前执行状态**：前端本地流程通过。提交后立即显示 Loading、按钮禁用，成功进入固定示例；真实请求时长、取消和超时恢复仍待 C 接口验证。

### TC07 接口失败

- **前置条件**：本地测试 UI 可运行；能在开发环境模拟断网或受控失败；记录原输入，不改生产 API。
- **输入**：有效简历与 JD；另用有效历史 id 测试只读加载失败。
- **操作步骤**：
  1. 模拟匹配请求失败，观察错误反馈及按钮。
  2. 核对输入与修正结果保留，解除故障后手动重试。
  3. 分别令历史列表和详情读取失败，检查重试入口及当前 id。
- **预期结果**：显示可读错误而非堆栈或 [object Object]；保留输入并允许重试；不显示假评分、不声称已保存；列表失败不伪装为空历史，详情网络失败不伪装为不存在；重试详情保持原 id。匹配超时可能已保存，跨请求去重策略待 A/C 确认。
- **当前执行状态**：本地失败模拟通过。错误可读、输入保留、可重试并成功进入固定示例；真实 HTTP 错误映射、超时与服务端保存状态仍待联调。

### TC08 空历史

- **前置条件**：独立 mock 明确设置空记录；后续真实测试采用专用空测试环境，禁止清空用户已有数据库。
- **输入**：空历史集合；正式响应封装以 A 确认的 schema 为准。
- **操作步骤**：
  1. 进入历史，等待加载完成。
  2. 检查空状态、布局和“新建分析”入口。
  3. 点击新建分析，确认去向；切换有记录状态作对照。
- **预期结果**：显示“还没有分析记录”，不白屏、不显示伪造记录；按钮能进入新建分析；只在成功空响应或明确 mock 空态下显示空历史。
- **当前执行状态**：mock 展示与恢复路径通过；真实空列表响应仍待 A 接口验证。

### TC09 历史详情不存在

- **前置条件**：有至少两条 id 不同的样例记录；真实阶段选格式合法且确认不存在的 id；只读验证，不删除现有记录。
- **输入**：不存在的 id；独立 mock 可使用 missing-demo，不能将其当作真实 UUID 请求后端。
- **操作步骤**：
  1. 通过项目实际导航方式直接访问不存在 id 的详情。
  2. 检查提示、返回历史与新建分析入口。
  3. 重排正常列表后，重新按原 id 打开某条详情；若项目使用 URL 路由，再检查刷新与浏览器前进/后退。
- **预期结果**：显示“这条分析记录不存在”；不回退到数组第一项、不显示旧详情；恢复入口可用；记录身份由 id 决定，列表排序改变不影响对应详情；网络异常另按 TC07 处理。
- **当前执行状态**：按 URL 中的字符串 id 打开、缺失 id 提示、返回路径和重排后身份稳定均通过 mock 检查；真实 404 契约仍待 A 确认。

### TC10 重复提交

- **前置条件**：与 TC06 相同，延迟足以观察快速连续操作；后续真实阶段使用专用测试记录观察保存次数。
- **输入**：RESUME-FULL + JD-BACKEND。
- **操作步骤**：
  1. 连续快速点击 5 次开始匹配，并混合使用 Enter 提交。
  2. 响应未完成时记录实际匹配请求数。
  3. 首次成功或失败结束后再主动提交一次，检查锁是否解除。
  4. 真实阶段核对首次在途操作对应的记录数，不以 DOM 中只显示一条代替保存验证。
- **预期结果**：首次在途操作最多一个匹配请求；按钮和事件处理双重防护；请求结束后可由用户发起下一次分析；不额外调用保存接口。跨标签页、网络重试或刷新后的服务端幂等性属于 A/C 待确认范围，不能由本测试推断。
- **当前执行状态**：前端本地流程通过。自动化同时触发两次提交只产生一次模拟任务，按钮和事件层均阻止在途重复；真实网络重试和服务端幂等仍待 A/C 验证。
