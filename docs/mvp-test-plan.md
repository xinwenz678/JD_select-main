# MVP 测试方案

版本：MVP 集成迭代测试方案 v1.0
适用范围：简历解析与诊断、JD 解析、规则匹配、证据定位、记录持久化、结果与历史页面
说明：本文定义测试范围、用例、环境、门禁和证据要求。最终测试报告、缺陷关闭报告和交付结论在 MVP 功能冻结后另行编写。

## 1. 测试目标

1. 验证用户能够完成“录入简历、解析与确认、输入 JD、匹配并保存、查看结果、从历史重新打开”的完整主流程。
2. 验证评分结果确定、可解释且限制在 0 到 100；技能未命中时不得虚构匹配。
3. 验证每条关键评分依据包含来源、类别、标签、原文行号和原文片段，并能随记录持久化。
4. 验证空输入、非法参数、服务失败、记录不存在等异常路径提供稳定且可读的反馈。
5. 验证新成员模块合并后没有破坏健康检查、解析、诊断、CRUD、构建和响应式布局。

## 2. 测试范围

### 2.1 本轮必须覆盖

- FastAPI 启动、健康检查、CORS、统一错误响应。
- 简历分段、基本信息、技能提取、规则诊断和用户修正确认。
- JD 必需、加分、否定技能分类及同义词归一化。
- 60/20/20 评分、匹配技能、缺失技能、建议和确定性。
- 原文证据定位，包括简历命中技能、JD 缺失要求、量化成果和动作动词。
- POST matches 保存以及 GET matches 最近列表、详情读取。
- 前端真实 API 请求状态、失败后保留输入、结果展示、历史回读。
- 1440、390、320 CSS 像素下关键页面布局。
- 无外部大模型 Key 时完整核心链路运行。

### 2.2 不纳入本轮阻断门禁

- STAR 大模型建议、TXT 或 DOCX 上传、多 JD 对比、PDF 或 Markdown 导出。
- 账号权限、并发压测、PostgreSQL、部署高可用。
- 最终视频、个人报告、交付压缩包及正式测试报告。

## 3. 测试环境矩阵

| 层级 | 基准环境 | 补充环境 |
|---|---|---|
| 操作系统 | Windows 11 | 一台未参与开发的 Windows 电脑用于冻结后冷启动 |
| Python | 项目 backend/.venv | README 支持的最低版本 |

每次自动化运行使用独立测试数据库或明确的 smoke 标识。不得使用真实简历、手机号、邮箱或生产数据库。

## 4. 进入与退出条件

### 4.1 进入条件

- main 或候选集成分支无未解决冲突。
- backend/.env 与 frontend/.env 已由示例配置生成，且没有真实密钥。
- Python 与 Node 依赖安装完成，锁文件校验通过。
- 8000 和 5173 端口可用。
- 五类验收数据已经脱敏并进入 sample_data。

### 4.2 MVP 测试退出条件

- scripts/verify.ps1 全部通过。
- 后端单元和 API 集成测试 100% 通过。
- D 的真实 UI smoke 100% 通过，无 pageerror 和非预期 console error。
- 完整、部分、低匹配、空输入、同义词五个验收场景全部通过。
- 结果页展示的每条证据能回到正确来源和原文行。
- 新保存记录能在最近 10 条中找到，详情与首次响应一致。
- 1440、390、320 和 720px 视口无横向溢出或信息截断。
- P0 和 P1 缺陷为 0；P2 缺陷有负责人、复现步骤和处理决定。
- 冷启动在 15 分钟内完成。
- 不存在真实隐私数据、明文密钥或未忽略数据库文件。

## 5. 测试数据设计

| 数据编号 | 简历 | JD | 预期 |
|---|---|---|---|
| TD01 | 完整 Python/FastAPI/SQL 简历，含数字和强动词 | Python 后端 JD | 高分；关键技能命中；证据含简历技能、量化和动作动词 |
| TD02 | 仅 Python/Excel | Python 后端 JD | 中低分；FastAPI、SQL 等出现在缺失项及 JD 原文证据 |
| TD03 | 市场运营简历 | Python 后端 JD | 低分；匹配技能为空或极少，不得猜测 |
| TD04 | 空白、纯空格、超长文本 | 任意有效 JD | 前端阻止或后端返回 422 与可读错误 |
| TD05 | pytorch、JS、golang、k8s 等别名 | 对应规范技能 JD | 归一化为 PyTorch、JavaScript、Go、Kubernetes |
| TD06 | 包含“不要求 Docker”等否定表达 | DevOps JD | 否定技能不进入必需或加分匹配 |
| TD07 | 同一数字或技能多次出现 | 对应 JD | 证据去重规则稳定，重复运行结果一致 |
| TD08 | 无量化、弱动词、缺经历区块 | 任意有效 JD | 证据质量降低并产生针对性建议 |

每条证据数据应保留固定换行，测试必须同时断言 line 和 text，防止只验证关键词而忽略定位偏移。

### 6.3 真实浏览器 smoke

脚本：frontend/tests/d-ui-smoke.mjs。

每次运行必须验证：

1. 首页进入新建分析。
2. 空简历时解析按钮不可用。
3. 载入脱敏样例并真实调用解析接口。
4. 运行真实诊断并显示可定位结果。
5. 确认简历后进入 JD 页面。
6. 模拟一次 matches 503，显示错误且保留输入。
7. 恢复后真实匹配并保存。
8. 结果页显示 0 到 100 分、分项、匹配/缺失技能、建议和免责说明。
9. 证据列表同时包含简历和 JD 来源，展示类别、标签、行号和原文。
10. 历史页按本次 UUID 找到记录，详情仍保留同一证据。
11. 390 和 320px 无横向溢出。
12. 无 pageerror；API 请求和状态写入 artifacts/report.json。

## 7. 手工验收场景

| 编号 | 步骤摘要 | 通过标准 |
|---|---|---|
| E2E-01 完整匹配 | TD01 完成全流程 | 高分、缺失少、证据逐条可核对 |
| E2E-02 部分匹配 | TD02 完成全流程 | 明确列出 FastAPI、SQL 等差距 |
| E2E-03 低匹配 | TD03 完成全流程 | 低分且不出现虚假技能 |
| E2E-04 空输入 | 分别提交空简历和空 JD | 焦点或提示定位到错误字段；无脏记录 |
| E2E-05 同义词 | 使用 TD05 | 规范技能名称一致，重复运行分数一致 |
| E2E-06 失败恢复 | 后端停止或拦截 503 后恢复 | 错误可读，输入保留，可重试成功 |
| E2E-07 历史回读 | 保存后刷新并从历史进入详情 | UUID、分数、证据与首次结果一致 |
| E2E-08 记录不存在 | 请求随机 UUID | 404 页面可恢复，不显示其他记录 |
| E2E-09 隐私 | 检查日志、仓库和错误响应 | 不输出完整简历、联系方式、密钥或栈信息 |
| E2E-10 响应式 | 桌面、手机、200% 缩放 | 内容可读，无横向滚动或按钮遮挡 |

## 8. 执行顺序与命令

第一阶段，快速静态与单元门禁：

    powershell -ExecutionPolicy Bypass -File scripts/verify.ps1 -SkipSmoke

第二阶段，算法边界回归：

    backend/.venv/Scripts/python.exe backend/scripts/validate_boundary.py

第三阶段，启动本地服务：

    powershell -ExecutionPolicy Bypass -File scripts/start.ps1

第四阶段，在 frontend 目录执行真实浏览器 smoke：

    设置 PLAYWRIGHT_MODULE_PATH 为可用 Playwright 包路径
    node tests/d-ui-smoke.mjs

第五阶段，在可视浏览器执行 E2E-01 到 E2E-10，并保存截图、录屏片段和缺陷编号。

## 9. 缺陷分级与回归规则

| 级别 | 判定 | 处理 |
|---|---|---|
| P0 | 无法启动、主流程中断、数据泄露、记录错配、分数越界 | 立即修复；不得进入下一阶段 |
| P1 | 主要页面不可用、证据行号错误、历史详情不一致、错误不可恢复 | 功能冻结前清零 |
| P2 | 文案、间距、低频兼容或不影响判断的样式问题 | 记录负责人和处理决定 |

每个缺陷至少记录环境、前置数据、步骤、预期、实际、截图或日志、修复提交和复验结果。修复后先运行最小相关测试，再运行 verify 和受影响的真实 E2E；无新改动时不重复扩大测试。

## 10. 测试证据与报告边界

本轮自动化证据保存在 frontend/tests/artifacts：

- report.json：浏览器、记录 UUID、分数、证据数量、请求及响应状态。
- real-result-desktop.png：桌面结果和证据列表。
- real-result-mobile.png：移动端结果和证据列表。

后端测试原始输出、五场景手工记录、缺陷关闭证据、冷启动计时和环境信息在 MVP 功能冻结后统一汇总为正式测试报告。本方案不提前给出“最终通过”或“可交付”结论。
