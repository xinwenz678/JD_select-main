# 三个核心页面的信息架构与低保真原型

日期：2026-09-08  
负责人：成员 D（结果体验、质量与展示）

## 1. 状态说明

本文定义新建分析、匹配结果、历史记录三页的结构、字段、按钮和状态。本轮已经将对应 mock 页面整合到 `JD_select-main/frontend/`，保留项目原有 React / TypeScript / Vite 技术栈、健康请求服务和 Vite 代理，没有新增业务 API。

真实后端当前只提供 `/api/health`。Result/History 使用固定合成记录；新建分析是输入原型。页面显著显示“业务数据为本地示例 · 未调用匹配接口 · 未保存”。

## 2. 全局结构

- 主导航：新建分析、匹配结果、历史记录。
- 页面层级：页面标题 → 当前状态 → 核心内容 → 下一步操作 → 后端健康检查。
- 匹配结果导航当前打开固定示例；未来真实结果应从匹配成功或历史详情进入。
- 详情使用记录 `id`，不使用数组下标作为 React key、路由或查找条件。
- 桌面内容居中；窄屏变为单列。岗位名、技能、建议、版本和 id 均可换行。
- 错误和状态不只靠颜色表达；导航后焦点进入页面主标题。

## 3. 页面一：新建分析

```text
┌ 新建分析 [当前] ── 匹配结果 ── 历史记录 ┐
│ MOCK：业务数据为本地示例                 │
│ 新建分析                                 │
│ [输入流程原型说明]                       │
│ 01 · 输入简历             [填入合成示例] │
│ [简历多行文本框……………………………………] │
│ [空输入提示 / 输入说明]                  │
│ [解析简历（待接入，禁用）]               │
│ 02 · 查看并修正解析结果                  │
│ [教育] [经历] [项目] [技能]              │
│ 03 · 输入岗位 JD                         │
│ [JD 多行文本框………………………………………]│
│ [开始匹配（待接入，禁用）]               │
│ 先查看结果体验 [打开固定结果示例]         │
└──────────────────────────────────────────┘
```

| 区域 | 字段/按钮 | 状态及行为 |
|---|---|---|
| 简历输入 | `resume` 文本框、“填入合成示例”、“解析简历” | 空白提示；输入保留在当前会话；真实解析未接入时按钮禁用 |
| 解析结果 | 教育、经历、项目、技能 | 当前仅在固定合成示例下显示预设结构，明确注明并非解析输出；输入改变后立即移除旧结构 |
| JD 输入 | `jd` 文本框、“开始匹配” | 空白提示；真实匹配未接入时按钮禁用 |
| Result 示例入口 | “打开固定结果示例” | 与输入内容无关，不计算、不保存 |
| 真实 Loading | “正在解析…”或“正在分析…” | 接口接入后才启用；在途禁止重复提交，不显示虚假百分比 |
| Error | 字段错误、解析失败、匹配失败 | 保留输入，提供重试；不输出堆栈或敏感内容 |

B 负责真实简历解析与编辑组件；C 负责匹配；D 只在契约明确后接入提交状态。不能擅自增加请求字段解决人工修正传递问题。

## 4. 页面二：匹配结果／历史详情

```text
┌ 返回历史                            ┐
│ 数据分析实习生        匹配分 72/100 │
│ 示例记录 · 未保存                   │
│ 匹配分用于辅助判断，不代表录用概率 │
│ 分项得分                           │
│ 必需技能 55  加分技能 12  证据 5  │
│ 匹配技能           缺失技能        │
│ Python / SQL       Tableau          │
│ 改进建议                           │
│ 评分依据 / 证据：暂未提供          │
│ 算法版本 rule-v1   记录 id demo-001│
│ [返回历史] [修改后重新分析]         │
└─────────────────────────────────────┘
```

| 字段/区域 | 展示规则 | 缺失或边界处理 |
|---|---|---|
| `id` | 关联当前结果、历史详情和导航 | 无 id 时不构造详情链接或声称已保存；示例 id 不冒充 UUID |
| `job_title` | 页面岗位标题 | 空值显示“未命名岗位”，不根据技能猜测 |
| `score` | 匹配分 `/ 100` | `0` 是有效分数；缺失显示“暂无评分”，前端不重算 |
| `score_breakdown.required_skills` | 必需技能得分 | 展示数值，不将 55 分解释为 55% |
| `score_breakdown.preferred_skills` | 加分技能得分 | 缺失显示“暂未提供”，0 正常显示 |
| `score_breakdown.evidence_quality` | 经历证据质量得分 | 得分不等于证据已可追溯 |
| `matched_skills` | 匹配技能标签 | 空数组显示“暂无匹配技能”，不虚构能力 |
| `missing_skills` | 缺失技能标签 | 空数组显示“未发现缺失技能”，不推导为录用 |
| `suggestions` | 建议列表 | 空数组显示“暂无改进建议”；对象结构待确认 |
| `algorithm_version` | 算法版本 | 缺失显示“版本信息暂未提供” |
| 评分依据/证据 | 显示服务端实际证据 | 用户 mock 没有证据字段，明确显示“暂无法核验”，不编造摘录 |
| 评分说明 | “匹配分用于辅助判断，不代表录用概率” | 正常结果和历史详情都显示 |

### 页面状态

| 状态 | 内容与操作 |
|---|---|
| normal | 完整示例结果、来源和未保存状态；返回与重新分析可用 |
| loading | “正在加载匹配结果…”；不显示上一条记录的旧分数 |
| error | 可读错误与重试；不伪装成功 |
| empty | “暂无匹配结果”，进入新建分析 |
| not-found | “这条分析记录不存在”，返回历史或新建分析 |

## 5. 页面三：历史记录

```text
┌ 历史记录 [当前]                       ┐
│ 最近分析（最多 10 条） [新建分析]     │
│ 岗位名称   匹配分  创建时间  查看详情 │
│ 数据分析…  72      …        →         │
│ Python…    48      …        →         │
│                                      │
│ 空状态：还没有分析记录 [新建分析]     │
└──────────────────────────────────────┘
```

| 字段/控件 | 行为 |
|---|---|
| 岗位名称 | 使用 `job_title`，空值为“未命名岗位”，长文本换行 |
| 匹配分数 | 0 正常显示；缺失不冒充 0 |
| 创建时间 | 带时区时间转换为浏览器本地时间；缺失或非法显示“时间暂未提供” |
| 查看详情 | 绑定该条 `id`；若用 URL，则编码 id；重排不影响对应关系 |
| 最近列表 | 最多展示 10 条，当前 mock 为 3 条固定合成记录 |
| 空历史 | 仅成功空响应或明确 mock 空态显示；不能将请求失败当作空记录 |
| 加载/失败 | 分别展示 Loading 和可重试错误 |

窄屏时每条记录改为卡片，仍完整展示岗位、分数、时间和详情入口。
