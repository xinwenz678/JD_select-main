## 2. 可展开的技术决策

### 决策一：先用 SQLite 完成本地演示

项目周期短，A3 需要稳定保存分析历史。SQLite 随 Python 可用，组员无需安装独立数据库服务。DATABASE_URL 仍保留配置入口，但当前没有验证 PostgreSQL 驱动与迁移。
证据：数据库构造、运行模板、重启测试。反思可写“降低了演示环境准备成本”，不能写成已经支持生产高并发。

### 决策二：计算和存储分离

C 负责评分，A 提供 create_record；存储服务只 flush，由编排决定 commit，异常时依赖回滚。
单独保存接口用于已有结果的演示，不生成分数。72 分是样例输入，不是算法性能证据。
证据：services/analysis_records.py、docs/api.md、事务回滚测试。

### 决策三：统一错误和数据边界

输入校验、找不到记录、数据库失败和未预期异常有明确状态/错误码，允许来源的错误响应保留 CORS 头。
记录输入、评分和结果为快照，PATCH 只改标题，避免修改原文后历史评分失去对应关系。
证据：errors.py、RecordUpdate、相应测试。

### 决策四：可复现环境需要完整依赖与冷启动

仅固定顶层 requirements 不足以固定间接依赖。A5 用递归锁版本校验及全新目录安装验证，安装入口保留个人 .env。
新目录验收仍是同一电脑，不能替代另一台电脑的复验。
证据：锁文件、check-lock.py、A5 验证记录。
