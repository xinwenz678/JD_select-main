# MVP 后续四人均衡任务计划

更新时间：2026-09-09
当前基线：main，Level 1 主流程已接通，后端 72 项测试与真实 UI smoke 已通过
分配原则：四个任务包各 25 点；成员 A、B继续迭代 MVP，成员 C、D立即开始实验材料与报告工作

## 1. 当前完成情况与剩余工作

### 已完成

- 简历文本录入、结构化解析、技能修正和规则诊断。
- JD 解析、技能词典、同义词、必需和加分技能识别。
- 60/20/20 可解释评分、缺失技能、改进建议和逐条原文证据。
- SQLite 保存、最近 10 条记录和历史详情。
- 真实前端主流程、失败恢复、移动端结果页面。
- 后端 72 项测试、规则边界脚本和真实 Edge UI smoke。

### MVP 冻结前仍需完成

1. 防止连续点击产生重复匹配记录，明确失败重试和事务语义。
2. 支持结果详情刷新、复制地址和浏览器前进后退；补齐不存在记录等恢复状态。
3. 建立前端 Vitest/组件测试门禁，并接入统一验证脚本。
4. 清理或明确标注不再使用的 mock 原型、旧测试说明和过期 Bug。
5. 复核输入上限、隐私日志、错误响应、证据行号和 README 冷启动流程。
6. 完成五个核心场景的正式验收，之后才能冻结为 mvp-rc1。

### 实验材料与报告仍需完成

1. 两款招聘产品竞品分析。
2. 五份 JD 与三份简历的 15 组 gap 分析。
3. 求职市场痛点分析、正式需求规格、用例图、架构图和 ER 图。
4. 算法、数据字典、API、测试方案与实际代码的一致性整理。
5. 四份个人实训报告。当前成员 C、D先写各自报告；成员 A、B在 MVP 冻结后补写自己的实施、问题和反思。
6. 最终测试报告、演示视频、字幕、交付压缩包和预检。这些必须在 MVP 冻结后定稿。

Level 2 的 STAR 大模型建议、文件上传、多 JD 对比和导出不作为当前阻断任务。只有下列四个任务包全部通过且还有余量时再考虑。

## 3. 第一部分：MVP 后端、数据与接口稳定性（成员 A，25 点）

### A7 匹配保存可靠性与重复记录策略（6 点）

任务：

- 为 POST /api/matches 明确“同一次点击只保存一次”的行为。
- 与成员 B 确认前端在途锁；后端评估最小幂等键或明确主动重试会新建记录。
- 增加评分成功但数据库保存失败时的事务回滚测试。
- 验证异常后数据库没有半条记录，后续正常请求仍可成功。
- 保留已有 SQLAlchemy 记录模型，不重新引入临时 sqlite3 存储。

产出：后端实现、事务测试、docs/api.md 中的重试语义。

验收：同时触发的一次用户操作只产生一条记录；保存失败后总记录数不变；恢复请求返回 200。

### A8 输入、错误与隐私边界（4 点）

任务：

- 对齐简历、JD、岗位名称的空白、长度和非法字符约束。
- 验证 404、405、422、500、503 错误格式一致。
- 确认日志不输出完整简历、JD、手机号、邮箱、SQL 参数和栈信息。
- 扫描仓库中的真实 .env、数据库、密钥和联系方式。
- 样例联系方式必须明确为合成数据。

产出：边界测试、隐私检查记录、更新 docs/api.md。

验收：所有异常有可读响应；Git 追踪内容不含真实密钥或数据库；日志检查通过。

### A9 原文证据与历史一致性复核（4 点）

任务：

- 抽查匹配技能、缺失技能、量化成果和动作动词四类 evidence_items。
- 验证 source、category、label、line、text 与原文一致。
- 验证创建响应和历史详情中的证据完全一致。
- 验证旧记录没有 evidence_items 时页面仍能显示空证据状态。
- 验证服务重启后记录仍可读取。

产出：补充后端证据测试和固定脱敏样例。

验收：至少四类证据各有一个自动断言；重启后 UUID、分数和证据不变。

### A10 API 与数据库设计冻结（4 点）

任务：

- 对照 Swagger 更新 docs/api.md，补齐 evidence_items 和错误示例。
- 更新 analysis_records 字段说明和 ER 图所需事实。
- 删除或标注已废弃的临时 analysis_store，不能误导后续维护者。
- 固定 algorithm_version 和 schema 兼容策略。
- 将技术事实交给成员 C、D用于设计与报告，避免他们猜测字段。

产出：冻结 API 文档、数据库字段表、给 C/D 的技术事实清单。

验收：OpenAPI、Pydantic schema、SQLAlchemy 模型和文档字段一致。

### A11 后端回归与集成交接（4 点）

任务：

- 运行全部 pytest、边界脚本、依赖锁和 pip check。
- 增加五场景所缺的 API 自动测试。
- 复核成员 B 涉及 API 的前端改动。
- 关闭后端 P0/P1 Bug，记录 P2。
- 提交小而可审查的 commit，不覆盖其他成员修改。

产出：通过的后端分支、命令输出、Bug 更新。

验收：后端测试 100% 通过；无未解决冲突；由成员 B 完成非作者复核。

### A12 README 后端运行部分（3 点）

任务：

- 更新 Python 版本、环境文件、数据库位置、API 文档和常见错误。
- 写清 setup、start、verify 和 stop。
- 说明 GitHub 代码不会自动运行，队友需在自己的电脑启动。
- 给成员 B冷启动使用，不进行口头补充。

产出：README 后端与故障排查部分。

验收：成员 B按 README 能完成后端健康检查、匹配保存和停止服务。

## 4. 第二部分：MVP 前端、真实流程与发布候选（成员 B，25 点）

### B7 防重复提交与失败恢复（5 点）

任务：

- 使用 ref 或等效在途锁，防止快速双击产生两次 POST。
- 请求期间禁用按钮并显示加载状态。
- 503、网络失败和超时后保留简历、JD、岗位名称。
- 提供明确重试入口；重试成功后只跳转到本次结果。
- 与成员 A联合验证记录数量。

产出：前端提交状态实现及自动测试。

验收：自动双击只捕获一次 POST；失败后输入不丢失；重试成功产生一条有效记录。

### B8 URL 路由、刷新与异常页面（6 点）

任务：

- 为首页、新建分析、历史、结果详情建立稳定 URL 或 hash 路由。
- 结果页刷新或复制到新标签后，按 UUID重新读取详情。
- 支持浏览器前进和后退。
- 非法 UUID、记录不存在、空历史、后端不可用分别显示可恢复页面。
- 不得回退到固定 demo 或其他记录。

产出：路由与详情加载实现、异常状态测试。

验收：复制详情地址可打开同一记录；刷新不丢失；404 不显示旧分数；返回历史行为正确。

### B9 前端自动测试门禁（5 点）

任务：

- 引入并锁定 Vitest、React Testing Library 和必要的 jsdom 依赖。
- 覆盖分数 0 与缺失值、证据列表、空历史、错误恢复和重复提交锁。
- 保留真实 Playwright smoke；组件测试不能替代 E2E。
- 在 package.json 增加 test 命令。
- 将 npm test 接入 scripts/verify.ps1。

产出：前端测试、依赖锁和统一验证脚本。

验收：npm test、npm run build、scripts/verify.ps1 和真实 smoke 全部通过；失败会返回非零状态。

### B10 正式入口与过期 mock 清理（3 点）

任务：

- 搜索 NewAnalysisPage、mocks、matchPreview 和旧截图的引用关系。
- 未使用代码先给出引用证据，再删除或移动到明确的 prototype 目录。
- 更新 docs/bug-list.md，关闭已经解决的旧依赖和契约问题。
- 更新演示脚本中的“当前为 mock”等过期描述。
- 正式入口不得出现“待接入”“固定示例结果”等误导文案。

产出：清晰的正式入口、准确的 Bug 清单和演示文案。

验收：构建、测试通过；从首页走完整流程时没有 mock 声明或死入口。

### B11 响应式、键盘与真实 smoke 扩展（3 点）

任务：

- 检查 1440、1024、768、390、320 和 720px 等效 200% 缩放。
- 键盘完成核心流程，焦点样式可见，表单标签可被识别。
- 将完整、部分、低匹配、空输入、同义词五场景纳入 smoke 或可重复手工脚本。
- 检查控制台无非预期错误。

产出：更新 d-ui-smoke.mjs 和自动化证据。

验收：关键宽度无横向溢出；五场景结果符合预期；pageerror 为 0。

### B12 冷启动候选与 mvp-rc1 准备（3 点）

任务：

- 从 GitHub 全新克隆，不复制当前 .venv、node_modules、.env 和数据库。
- 仅按 README 完成安装、启动、一次匹配、历史读取和停止。
- 记录耗时和问题，目标少于 15 分钟。
- 与成员 A合并后运行统一验证。
- P0/P1 清零后才建议创建 mvp-rc1，不自行提前打标签。

产出：冷启动记录、候选提交哈希、剩余 Bug 清单。

验收：干净环境可运行；统一验证通过；没有未解决 P0/P1。

验收：所有材料都有负责人和完成条件；运行预检时能准确指出尚未到齐的最终文件。

## 7. 并行顺序与交接点

### 立即并行

- 成员 A创建后端稳定性分支，完成 A7-A12。
- 成员 B创建前端稳定性分支，完成 B7-B12。
- 成员 C开始 C7-C12，不等待代码冻结；最终字段和截图留占位。
- 成员 D开始 D7-D12，不等待代码冻结；最终结果和视频留占位。

### 第一次交接：接口事实冻结

成员 A向 B、C、D提供最终 API、数据库和错误格式。成员 B确认前端调用无冲突；成员 C更新架构和需求；成员 D更新算法与演示材料。

### 第二次交接：MVP 候选冻结

A、B分支合并后运行后端测试、前端测试、build、规则边界和真实 smoke。P0/P1 清零后建立 mvp-rc1 候选。冻结后不新增 P1 功能、不重构公共接口。

### 冻结后共同完成

1. 成员 C按固定数据执行完整、部分和同义词场景。
2. 成员 D执行低匹配、空输入、响应式和历史回读场景。
3. 成员 A复核 API、数据库、日志和隐私。
4. 成员 B复核前端、冷启动和浏览器控制台。
5. D汇总正式测试报告，但每条结果由实际执行人签字。
6. 四人各自完成个人报告最终版。
7. 四人按演示脚本录制各自负责段落。
8. C、D检查材料，A、B检查源码包和冷启动。
9. 组长统一打包、备份并提交。

## 8. 每人完成定义

每个 25 点任务包只有同时满足以下条件才算完成：

- 产出已提交到个人分支，并由至少一名非作者复核。
- 正常路径和异常路径有测试、观察记录或明确证据。
- 文档、Swagger、界面和代码事实一致。
- 不包含真实简历、联系方式、密钥、数据库或本机路径。
- 报告中的个人实施、问题、AI 使用和反思由本人完成。
- 未冻结的数据不提前写成最终测试结论。
- 不删除其他成员正确修改，不扩大当前 MVP 范围。
