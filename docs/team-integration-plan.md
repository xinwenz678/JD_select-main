| 事项 | 已发现的具体差异/问题 | 需要谁确认 |
|---|---|---|

| 岗位标题 | D 页面需要 `job_title`，MVP 的匹配响应示例未包含该字段 | A/C 明确响应还是详情可提供；缺失时 D 使用占位，不自行造标题 |
| 评分证据 | D 需要可追溯依据，但 mock 只提供 `evidence_quality` 数值 | C 给实际证据结构和缺失语义；D 不从分数推断原文 |
| 列表与时间 | 当前没有可运行的列表封装、排序和时区契约 | A 给真实 JSON，确认最近 10 条、`created_at` 格式及详情 id |
| 建议及错误 | 本地建议是字符串数组，真实元素和错误结构未冻结 | A/C 给成功、校验失败、404、服务器错误样例；D 做展示适配 |

| 重新分析 | mock 详情没有原始简历/JD，当前只返回输入页 | A/B/C 确认真实原文与修正结果的可用性；D 只回填实际返回的数据 |
| 字段和路由归属 | B/D 都会修改新建页，C/A 都会涉及 matches 路由 | 指定每个共享文件的主改人；同一 HTTP 方法和路径只注册一次 |

## 4. 怎么整合为一个项目

### 4.1 统一开发入口

共享仓库根目录继续使用已有的 `backend/`、`frontend/`、`docs/`、`sample_data/` 和根 README。每个人提交成员分支及 PR；A 维护团队确认的集成分支，保留可运行的 `main`。

D 的旧 `output/` 仅作本机草稿备份，不作为第二个要启动的前端。整合后用户只打开一个前端地址，原有代理连接同一个后端。

### 4.2 按依赖分批合入

| 阶段 | 负责人及输入 | 做什么 | 通过后再进入下一阶段 |
|---|---|---|---|
| 1. 统一基线 | A + 所有人分支/哈希 | 对齐框架、依赖、目录和已确认契约 | 所有人能按同一 README 启动 |
| 2. 评审 D mock | D 提交文件清单，A/B/C 评审 | 先把三页展示、状态、测试和文档合入集成分支，保留明确 mock 标识 | 构建及 mock 检查在该分支可复现 |
| 3. 后端模块接通 | B 解析、C 匹配、A 持久化与路由协调 | 按依赖顺序注册模块；C 调 A 的存储能力，避免重复 matches 路由 | API 级解析→匹配→保存→列表/详情可复现 |
| 4. D 接真实页面 | B 的编辑确认组件 + A/C 真实响应 | D 接请求状态和展示适配，A/B 协助共享入口冲突处理 | 一份简历/JD 能从输入进入真实结果并打开同 id 历史 |
| 5. 联合验收 | 全组同一集成提交 | 执行 TC01–TC10，D 记录 Bug，各归属成员修复后复验 | 5 个主场景通过；P0/P1 关闭且有证据 |
| 6. 正式交付 | A 统筹版本，D 统筹演示 | 按评审流程合入主线，冻结录屏版本，补齐字幕/报告和最终目录 | MP4 小于 10 分钟，文件命名/内容/可运行性均核验 |

B、C、A 的独立模块准备可同时推进；表格描述的是合入与验证门槛，不要求大家串行等待。如果 A 的只读历史先就绪，D 可先接列表/详情，但最终仍要验证真实匹配产生的记录。

### 4.3 D 接入真实数据时要改哪里

- `App.tsx`：把固定的 `demoHistory`、`findDemoResult` 和 `demo-001` 成功跳转改为确认后的请求结果与服务端 id；路由结构尽量沿用。
- `NewAnalysisPage.tsx`：嵌入 B 的解析编辑确认组件，真实提交传递确认后的数据。当前 `onSubmitPreview` 只接收模拟结果选项，不能仅换一个 URL 就当作接好接口。
- `services/`：沿用当前服务目录，添加调用已确认 API 的客户端和响应映射；`types.ts` 保持展示模型，字段变化集中在映射处处理。
- `ResultPage.tsx`：使用真实响应与证据；只有服务端明确确认后才显示“已保存”。
- `HistoryPage.tsx`：消费 A 返回的列表顺序，按真实 id 查询详情；成功空列表、404 和普通网络失败分别处理。
- 提交时固定本次输入快照，等待期间修改输入、离开页面、请求超时或旧响应迟到时不误显示结果；这些行为需要追加真实链路验证。
- mock 保留为明确的演示/测试入口；真实模式失败时显示错误，不悄悄回退到固定示例。移除真实页面里的“示例条数”等硬编码文案。

这些是下一阶段的改动范围说明，本轮没有实现新接口或执行这些改动。

### 4.4 共享文件的冲突处理

| 文件或区域 | 协作方式 |
|---|---|
| `frontend/src/App.tsx`、新建页 | D 负责页面编排；B 负责简历组件；A 协助路由和入口整合，逐段合并 |
| `frontend/src/style.css` | B/D 检查类名和样式作用范围，避免覆盖彼此控件 |
| `backend/app/main.py`、路由注册 | A 统一接入 B/C 路由并检查重复注册 |
| 公共 schema、接口文档 | 服务提供者和调用者共同确认，A 维护版本 |
| 依赖清单和锁文件 | A 汇总实际新增依赖，使用团队统一包管理器，其他人重新安装 |
| README、handoff | 保留各人成果，添加带日期的增量；把本机限制与共享仓库状态分开表述 |
