# MVP 验收场景与 D 侧 UI 测试计划

日期：2026-09-08  
负责人：成员 D（结果体验、质量与展示）

## 1. 测试状态

本轮已把 D 的 Result/History mock 页面和新建分析输入原型整合到 `JD_select-main`。前后端可以启动；`GET /api/health`、`/docs` 和前端代理健康检查成功。OpenAPI 当前只有 `/api/health`，`/api/matches` 列表和详情返回 404。

因此：UI mock 检查已经执行，但 TC01–TC10 的真实业务链路没有执行。固定 72 分不能证明算法正确，状态切换不能证明真实请求、保存或匹配防重复提交完成。

## 2. 执行原则

- 使用合成输入，不含真实姓名、电话、邮箱或密钥。
- 高、中、低分的具体阈值由 C 根据确认后的评分规则给出，D 不在前端修改分数凑结果。
- 分项和及上限按正式契约验收；附件建议的 60/20/20 在代码确认前不能作为已实现事实。
- 历史详情使用服务端实际返回的 `id`；mock 的 `demo-001` 不作为真实 UUID 请求后端。
- 请求失败与空历史必须分开；0 分与缺失评分必须分开。
- 每个用例保存实际环境、提交、输入、结果和证据；未执行就标“待验证”。

## 4. TC01 完整匹配

- **预期结果**：高分；Python/FastAPI/SQL/数据分析等被正确识别，缺失项较少；证据来自真实输入；结果与同 id 历史详情一致；分数高于 TC02/TC03。

## 7. TC04 空输入

- **前置条件**：新建分析真实提交 UI 已接入，浏览器可观察网络请求。
- **输入**：空简历+有效 JD、有效简历+空 JD、两者都空、仅空格/换行。
- **操作步骤**：分别尝试解析或匹配；观察字段提示和请求；补齐输入后再次提交。
- **预期结果**：trim 后为空时禁止提交并给出“请先输入简历内容”或“请先输入岗位 JD”；不发送无效请求，不清空其他有效输入。
- **当前状态**：原型能展示空输入提示，但真实按钮禁用；完整用例待验证。

## 8. TC05 同义词

- **前置条件**：C 的词典和归一化链路可用；两次分析使用相同版本和 JD。
- **输入**：SYNONYM 的简历 A、B。
- **操作步骤**：分别解析和匹配；比较归一化名称、技能集合和得分；再在同一简历重复别名。
- **预期结果**：PyTorch/pytorch、JS/JavaScript 分别识别为同一技能；大小写和别名不改变对应评分；重复别名不重复计分或显示。
- **当前状态**：待 C 实现后验证，D 不伪造归一化结果。

## 9. TC06 Loading

- **前置条件**：真实匹配提交 UI 已接入；测试环境可延迟响应。
- **输入**：有效简历与 JD。
- **操作步骤**：点击开始匹配；响应前观察页面并尝试再次提交；分别观察成功和失败后的状态。
- **预期结果**：立即显示可读 Loading；按钮禁用且事件层拦截重复；不显示虚假百分比；结束后 Loading 消失并恢复正确操作。
- **当前状态**：Result 的 loading 视觉状态通过；真实提交生命周期待验证。

## 10. TC07 接口失败

- **前置条件**：真实业务 UI 可运行；开发环境能模拟受控失败。
- **输入**：有效简历/JD；另使用有效历史 id 测试读取失败。
- **操作步骤**：模拟匹配、历史列表、详情请求失败；检查错误、输入保留和重试。
- **预期结果**：显示可读错误而非堆栈或 `[object Object]`；保留输入；不显示假评分或已保存；列表失败不伪装空历史，详情网络失败不伪装不存在。
- **当前状态**：mock error 状态和真实健康检查失败重试通过；业务接口失败待验证。

## 11. TC08 空历史

- **前置条件**：mock 设为空集合；真实阶段使用专用空测试环境，不清空用户数据。
- **输入**：空历史集合或成功空响应。
- **操作步骤**：进入历史；检查空状态；点击新建分析。
- **预期结果**：显示“还没有分析记录”，不白屏、不显示伪造记录；入口进入新建分析；读取失败不显示该空态。
- **当前状态**：mock 展示与恢复路径通过，真实接口待验证。

## 12. TC09 历史详情不存在

- **前置条件**：有多个不同 id 的样例；真实阶段选择格式合法且确认不存在的 id。
- **输入**：`missing-demo`（仅 mock）或真实不存在测试 id。
- **操作步骤**：访问不存在详情；检查提示和恢复；重排列表后按原 id 打开正常详情；检查刷新与浏览器前进后退。
- **预期结果**：提示“这条分析记录不存在”；不回退到第一条或显示旧详情；排序不影响 id 对应；网络失败另按 TC07。
- **当前状态**：真实 API 已通过；不存在 UUID 显示明确恢复状态，不显示旧分数，返回历史与新建分析可用。

## 13. TC10 重复提交

- **前置条件**：真实匹配按钮已接入，响应有可观察延迟；使用专用测试数据。
- **输入**：有效简历和 JD。
- **操作步骤**：快速点击五次并混合 Enter；记录在途请求数；结束后再次主动提交；真实阶段核对保存记录数。
- **预期结果**：首次在途操作最多一个匹配请求；按钮和事件双重防护；结束后可以再次提交；不额外调用保存接口。
- **当前状态**：真实匹配已通过；同步在途锁使快速双击只产生一个 POST 和一条记录，请求结束后可主动再次分析。
