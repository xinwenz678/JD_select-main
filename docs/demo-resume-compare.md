# 原始 / 优化简历对比演示（成员 B，任务 B6）

> 用途：答辩 PPT、演示视频中展示"简历诊断→针对性优化→再次诊断"闭环的固定素材。
> 数据真实性：下文所有解析与诊断结果均为本仓库后端真实输出（rule-v1，2026-09-09 复测），
> 同一人在同一规则下前后对比，杜绝"换人换分数"的不可比问题。

## 1. 素材

| 阶段 | 文件 | 说明 |
|---|---|---|
| 原始 | `sample_data/resume_weak.txt` | "赵强"，四类典型问题：教育无年份、经历无动词开头、无量化结果、技能仅 1 项 |
| 优化 | `sample_data/resume_optimized.txt` | 同人优化版：补年份、动词开头、补量化、扩技能、补项目区块 |

## 2. 实测输出对比（后端 rule-v1 实际返回）

### 2.1 解析结果

| 指标 | 原始 | 优化 |
|---|---|---|
| 识别区块 | education / experience / skills | education / experience / projects / skills |
| 技能词数量 | 1（Java） | 11（Java, SQL, JavaScript, Python, Spring Boot, MyBatis, MySQL, Redis, Git, Docker, Linux） |
| 区块完整性 | 缺项目经历 | 4 区块齐全 |

### 2.2 诊断结果

| 分类 | 原始 | 优化 |
|---|---|---|
| quantified（量化亮点） | 0 | **5** |
| action_verb（动词建议） | 1 | 0 |
| suggestion（结构建议） | 3 | 0 |
| 合计 | 4 | 5（全部为正向亮点） |

原始版具体建议（带原文行号）：
- L10 实习经历行不以动作动词开头 → 建议改写（action_verb）；
- L11 以"修复"开头但无量化 → 建议补数字（suggestion）；
- L6 教育背景无起止年份 → 建议补时间线（suggestion）；
- 技能词仅 1 项 → 建议补充 3-6 项并对齐 JD（suggestion）。

## 3. 逐条修改对照（从原始到优化做了什么）

| 原始问题 | 诊断建议 | 优化动作 | 优化后效果 |
|---|---|---|---|
| `XX大学 计算机科学与技术 本科`（无年份） | 教育经历未识别到起止年份 | 改为 `2021.09 - 2025.06  XX大学  计算机科学与技术  本科`，加主修课程 | 时间线完整，建议消除 |
| `数据平台接口开发与联调工作`（无动词） | 建议以动作动词开头 | 改为 `负责数据平台接口开发与联调，基于 Java/Spring Boot 交付 6 个查询接口` | 命中 quantified（6 个） |
| `修复线上系统若干历史遗留问题…`（无数字） | 有动作但缺量化 | 改为 `主导修复线上缺陷 23 个，核心接口 P99 延迟降低 35%，回归用例通过 40 条` | 命中 quantified×2 |
| 技能区只有 `Java` | 技能词仅 1 项，覆盖偏窄 | 扩展为 4 行 11 项，并对齐后端岗位常用栈 | 建议消除，可匹配技能增多 |
| 无项目区块 | 未识别到实习/项目区块 | 补 1 段课程项目（动词 + 量化） | 4 区块齐全，quantified +2 |

## 4. 演示操作步骤（约 2 分钟）

1. 打开系统"简历录入"页，点"填充示例"选**原始简历**（内容同 `resume_weak.txt`）；
2. 点"解析并诊断"，指出：右侧技能只有 Java、诊断给出 4 条建议且能定位到行；
3. 切"优化简历"（内容同 `resume_optimized.txt`）再解析一次；
4. 对比诊断面板：0 建议 + 5 处量化亮点，技能 11 项；
5. 收尾话术："诊断系统给的不是一句空话，而是带行号的修改点——照着改完，下一轮诊断就能证明优化有效。"

## 5. 讲解口径（防止被提问卡住）

- **为什么结果可复现**：规则引擎 `rule-v1` 无随机性，同一文本任何时候诊断结果一致；
- **量化"5"是不是算法自嗨**：每一条 quantified 都对应原文中真实存在的"数字+单位/百分比"，
  点击即定位，系统只是提示"数据点越具体越可信"；
- **为什么强调同人对比**：原始/优化用同一个"赵强"，避免拿两份不同简历硬比造成的口径质疑；
- **局限坦诚版**：规则无法理解"没有数字但确实做了事"的表述，所以演示刻意选择先改出数字，
  这正是报告"展望"部分承认的规则引擎边界。
